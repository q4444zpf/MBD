## 1. 产品概述

### 1.1 MBD 定义

本产品中的 MBD 指 Model-Based Design（基于模型的设计）。其核心是先建立可计算、可验证的工程模型，再以模型贯穿对象设计、设备与传感器布置、算法构建、工况仿真、调度控制和设计验证全过程。

**边界说明：** 机械制造领域的 MBD 有时表示 Model-Based Definition（基于模型的定义）。本产品明确采用 Model-Based Design 的含义。

### 1.2 背景与问题

- 水利工程涉及多类设计规范、设备标准、监测要求和数据标准，规则复杂且容易漏填、错填。
- 构筑物、设备、传感器、算法和工况通常分散在不同工具或文档中，缺少统一对象模型。
- 传统固定表单难以覆盖不同工程类型及自定义设备，扩展成本高。
- 设计、仿真、调度和控制相互割裂，模型间算法调用与联合验证困难。
- 评审环节缺少可追溯的自动校验结果，难以快速回答“工程在什么工况下可以运行、属于什么等级”。

### 1.3 产品定位

面向水利工程设计与建模人员的 MBD 设计与验证平台。产品以水利工程对象模型为中心，提供可配置对象库、拖拽式设计工作台、自然语言设计助手、算法与工况编排、联合仿真、标准校验和验证报告能力。

### 1.4 当前水利设计院常用做法与机会

当前水利设计院的信息化成熟度因单位、专业和项目类型而异，本节描述的是需要在立项调研中验证的行业共性，不代表所有设计院均采用完全相同的流程。

| 现状 | 常用做法 | 主要问题 | 产品机会 |
| --- | --- | --- | --- |
| 二维设计仍是主流 | 以 CAD 图纸、二维流程图、断面图和表格表达方案 | 图形与计算参数分离，设计变更难同步到计算和校核 | 将二维拓扑与结构化对象、参数、规则和运行结果建立绑定 |
| 文件驱动为主 | 通过 Word、Excel、PDF、图纸、计算书和共享目录传递输入与成果 | 版本命名依赖人工，数据来源和修改链难追溯 | 用项目、模型版本、场景、运行快照和成果链统一管理 |
| 专业软件分散 | 水文、水力、水质、调度、控制和制图分别使用不同软件 | 输入重复录入，接口格式不统一，联合验证成本高 | 建立标准对象模型与求解器适配层，编排跨模型计算 |
| 规范检索依赖经验 | 工程师从规范、企业标准、历史计算书中人工查找条款 | 新旧版本混用、适用条件判断困难、遗漏风险高 | 建设有版本、效力、权限和原文定位的知识库与规则库 |
| BIM/GIS 局部应用 | BIM 多用于重点构筑物或展示，GIS 多用于底图、空间分析和资产定位 | 尚未普遍贯穿模型计算、设计校核和成果审批全流程 | 先提供开放接口和关联能力，再按价值扩展二维/三维协同 |
| 评审依赖离线流转 | 通过邮件、会议纪要、批注文件完成复核和审批 | 意见、修改、计算输入和最终成果之间关系不清晰 | 用版本化工作流、问题闭环和不可变成果形成审计链 |

因此，产品机会不在于简单替换现有绘图或专业计算软件，而在于建立跨工具的统一水利对象语义、可复现运行上下文和可审计工程流程。

### 1.5 建议方案

建设一套水利专用 MBD 平台，以可配置组件为基础，在可视化画布中构建工程拓扑；以工程模型、方案场景和运行快照管理仿真、控制与调度计算；以知识库和检索增强生成支持自然语言建模、设计文件与校核报告草案；以工作流和成果管理固化复核、审批、发布和归档过程。

工程数值计算、拓扑合法性、单位、参数范围及强制性规则由确定性规则引擎或专业求解器执行。AI 仅负责意图理解、授权知识检索、草案生成和结果解释；AI 输出不得直接成为正式模型或成果，必须包含可定位引用，并经过确定性校验与人工审批。

## 2. 产品目标与成功指标

### 2.1 产品目标

1. 让设计人员通过拖拽和参数配置完成水利对象拓扑及可运行模型的构建。
2. 建立可扩展、可版本化、可治理的水利组件与对象体系。
3. 打通工程模型、算法、工况、仿真、调度、校核与成果的上下文。
4. 将规范、设计规则、校核文件和历史成果转化为可检索、可引用的知识资产。
5. 固化设计、校核、审批和归档流程，使模型和成果可复现、可追溯、可审计。

### 2.2 成功指标

上线前须采集至少 2 至 4 周现状数据，并由产品、领域、技术和验收方共同冻结统计口径。

| 目标 | 指标口径 | V1.0 建议目标 |
| --- | --- | --- |
| 建模效率 | 标准案例从需求输入到可运行模型的中位耗时 | 较现状下降不少于 40% |
| 上手效率 | 新用户完成 2 小时培训后独立搭建标准拓扑的比例 | 不少于 80% |
| 组件复用 | 新模型中引用已发布组件模板的节点占比 | 不少于 80% |
| 自动校核价值 | 自动校核发现的问题占全部发现问题的比例 | 不少于 70% |
| 文档解析 | 受支持文档解析成功率 | 不少于 98% |
| 原文定位 | 已生成切片可回到页码、章节或表格的比例 | 100% |
| 检索质量 | 领域评测集 Recall@10 与 nDCG@10 | 不少于 90% 与 0.80 |
| AI 引用 | 关键结论具有有效引用的比例 | 100% |
| AI 草案质量 | 草案首次通过或仅需轻微修改的比例 | 不少于 70% |
| 校核安全 | 高风险规则集严重问题召回率 | 不少于 95% |
| 运行稳定 | 排除输入错误后的模型任务成功率 | 不少于 98% |
| 联合仿真复现 | 同一快照重复运行的黄金算例结果 | 关键指标全部处于领域专家冻结的容差内 |
| 两类案例交付 | 污水处理与明渠输水 P0 案例包端到端验收 | 2/2 闭环通过，冻结对象覆盖率 100%，阻断错误为 0 |
| 标准接口交付 | INT-01 至 INT-10 契约包和模拟测试 | 10/10 交付并通过提供方与消费方契约测试 |
| 报告正确性 | 适用报告格式生成、必填来源和结构化数值一致性 | 成功率、来源完整率和数值一致率均为 100%，未替换占位符为 0 |
| 成果追溯 | 抽检成果具备完整版本与审批链的比例 | 100% |
| 系统可用性 | MVP 月度可用性 | 不少于 99.5% |

### 2.3 产品原则

- **模型为中心：** 图形、参数、算法、数据、规则、运行和成果均关联到统一模型对象。
- **发布即不可变：** 已发布组件、模型、规则、知识、工作流和成果不得原地覆盖。
- **计算可复现：** 正式运行必须冻结全部输入、依赖及环境版本。
- **确定性优先：** 工程数值和强制性判断不能只由语言模型给出。
- **人机协同：** AI 只生成草案，引用、校验、人工复核和审批缺一不可。
- **权限同源：** 页面、API、搜索、向量检索、文件下载和 AI 上下文使用同一权限结论。
- **开放集成：** 通过版本化适配器接入专业求解器、数据源、BIM、GIS 和档案系统。

## 3. 用户角色与职责边界

### 3.1 用户角色

| 角色 | 主要任务 | 核心诉求 |
| --- | --- | --- |
| 系统管理员 | 组织、用户、角色、权限、菜单、参数、日志与服务治理 | 系统安全可控，关键操作有审计 |
| 组件管理员与领域专家 | 组件模板、参数 Schema、端口、单位、规则、版本 | 标准组件可复用，升级不破坏历史模型 |
| 知识管理员 | 文档解析、切片、元数据、审核、发布、废止 | AI 仅使用有效且获授权的知识 |
| 模型、算法与工作流管理员 | 模型类型、算法资产、求解器适配器、流程模板 | 项目采用统一模型、算法和流程规范 |
| 项目经理 | 项目成员、里程碑、流程发起、成果提交 | 掌握进度、阻塞和审批状态 |
| 设计与建模工程师 | 拓扑、参数、场景、运行、AI 草案 | 快速完成可运行、可解释的设计 |
| 校核与审核人员 | 规则执行、问题复核、退回、批准 | 结论有依据，修改可追踪 |
| 查看与审计人员 | 查询、追溯、授权下载、日志导出 | 不修改数据即可核查全过程 |

### 3.2 管理端与用户端边界

| 入口 | 能力范围 | 责任边界 |
| --- | --- | --- |
| 管理端 | 模型类型、工作流模板、智能体、知识、组件、成果策略、用户、角色、权限、菜单、日志 | 负责组织级标准、资产治理和安全审计，不默认参与项目工程设计 |
| 用户端 | 项目、拖拽建模、参数配置、校核、AI 对话、模型运行、测试报告、评估报告、成果 | 负责项目内生产、复核和交付，不能发布全局组件或平台规则 |
| 系统服务 | 鉴权、运行调度、规则执行、审计、存储、索引和健康监测 | 默认拒绝；任何未授权对象在页面、搜索和 API 中均不可见 |

### 3.3 职责分离规则

- 组件管理员可发布全局模板，但不能静默覆盖项目中的组件实例。
- 知识管理员负责知识有效性和权限，不负责批准 AI 生成的工程成果。
- 项目经理可发起组织已发布的工作流并选用已发布算法，但不能修改已发布模板或算法逻辑。
- 校核人员原则上不直接修改送审模型，只能提出问题、退回或批准。
- 是否允许设计人审批本人提交由组织策略决定；高风险项目建议强制职责分离。
- 系统管理员默认无权查看业务正文；因运维确需访问时必须临时授权并审计。

## 4. 产品范围与非目标

### 4.1 MVP 范围

- 登录、用户、组织、角色、权限、项目与审计。
- 水利组件目录、低代码组件配置、端口与参数 Schema、版本发布。
- 拖拽式拓扑构建、连接校验、参数配置、基础规则校核。
- 工程模型、版本、方案场景、运行快照、算法资产、基础联合仿真和至少一类专业求解器接入。
- 基础 DAG 工作流、人工审批、失败重试和运行留痕。
- 文档上传、解析、切片、元数据、全文与向量索引、审核与发布。
- 自然语言模型草案、设计文件草案、校核报告草案及强制引用。
- 成果预览、版本、审批、发布、归档和交付包。
- 首期固定建设污水处理与明渠输水两个 P0 业务案例包，两类案例均须完成对象建库、拓扑组织、参数配置、模型计算、规范校核、报告生成、审批和归档闭环。

### 4.2 非目标

- MVP 不覆盖所有水利专业和全部对象，优先验证代表性场景的端到端闭环。
- MVP 不自行研发通用水文、水动力、水质和优化调度求解器，优先接入成熟引擎。
- MVP 不替代 GIS、BIM、CAD 和生产级 SCADA、PLC，仅提供必要关联、数据交换和策略验证能力。
- MVP 不支持未经人工审批的自动设计发布、自动校核签署或生产控制下发。
- MVP 不建设通用算法开发 IDE；自定义算法通过受控包或适配器接入，复杂多求解器联合仿真进入后续版本。
- MVP 不建设通用企业文档管理、即时通信、财务或采购系统。
- MVP 不支持任意流程回边、无限循环、大规模实时协同编辑和跨组织联合审批；循环计算封装为具有最大次数、收敛条件和超时的有界迭代节点，外层流程仍保持 DAG。
- MVP 不将 AI 回答视为工程依据；没有可靠引用的内容不得进入已验证或正式发布状态。

### 4.3 立项假设

- 主要客户暂按水利设计院、工程咨询单位、水利管理部门和工程业主考虑。
- 部署暂按私有化或专有云优先，是否允许调用外部大模型由数据分级策略决定。
- MVP 建议周期为 4 至 6 个月，至少接入一类专业求解器。
- 典型工程规模、并发量、适用标准、成果模板、电子签章和密级要求均为 TBD。

## 5. 核心领域模型

### 5.1 主对象链

产品以以下对象链组织业务：

`组件模板 -> 组件实例 -> 工程模型 -> 方案场景 -> 计算任务 -> 运行尝试 -> 成果`

工作流实例是上述对象链的编排上下文，可关联一个或多个计算任务；一个计算任务首次执行或重试时分别形成不可变的运行尝试。三类标识必须独立，成果同时记录所属工作流实例、计算任务和成功运行尝试（如适用）。

| 对象 | 定义 | 关键内容 |
| --- | --- | --- |
| 组件模板 | 可复用的水利对象定义 | 图标、端口、参数 Schema、单位、规则、模型适配器 |
| 组件实例 | 工程模型中的具体对象 | 坐标、实例参数、连接、数据绑定、模板版本 |
| 工程模型 | 组件实例和连接形成的系统 | 拓扑、全局参数、子模型、生命周期、版本 |
| 方案场景 | 同一模型的一组运行条件 | 边界、初始条件、计算时段、工况、调度策略、参数覆盖 |
| 工作流实例 | 一次已发布流程的执行 | 流程定义版本、输入快照、节点状态、节点尝试、实际输入输出引用、日志 |
| 计算任务 | 一次模型或求解器计算请求 | 模型版本、输入快照、任务状态、父工作流实例、结果清单 |
| 运行尝试 | 计算任务的一次具体执行 | 尝试序号、适配器与环境版本、日志、状态、资源消耗、父任务 |
| 成果 | 运行或人工提交产生的交付物 | 模型包、数据、图表、设计文件、校核报告、审批记录 |

### 5.2 支撑对象

| 对象 | 作用 |
| --- | --- |
| 项目 | 隔离成员、模型、知识、工作流、运行和成果的数据边界 |
| 连接 | 描述组件端口之间的水力、工艺、数据或控制关系 |
| 数据集 | 保存边界、初始、监测、历史及标定数据及其版本 |
| 算法模型 | 保存水文、水动力、控制或调度算法的输入输出、单位、依赖、运行环境及版本 |
| 规则与规则集 | 保存可执行校核逻辑、适用范围、依据、级别及版本 |
| 知识文档与切片 | 保存原文件、结构化内容、可定位证据和检索索引 |
| 工作流模板与实例 | 定义过程编排，并保存每次执行的节点状态和证据 |
| 审批任务 | 绑定待审对象、版本、处理人、意见、结论与时间 |
| 审计事件 | 记录主体、动作、对象、前后值、时间、来源和追踪标识 |

### 5.3 六类核心信息模型

六类信息模型是跨模块数据契约视图，不替代第 5.1 节的业务生命周期链。所有信息模型至少包含 `id`、租户与项目、Schema 版本、业务版本、状态、访问控制、内容哈希、来源以及创建修改信息，并纳入统一 Schema 注册、兼容性检查和迁移管理。

| 编号 | 信息模型 | 必备内容 | 验收要点 |
| --- | --- | --- | --- |
| IM-01 | 工程对象信息模型 | 对象编码、类型与模板版本、图形、设计/运行/计算参数、单位、约束、端口、空间高程、数据绑定 | JSON Schema 校验通过；导入导出往返后字段、单位和引用无损；已发布版本不可原地修改 |
| IM-02 | 拓扑关系信息模型 | 图版本、源/目标对象与端口、上下游、连接、包含、控制、方向、介质、量纲、基数及条件 | 保存重开后语义不变；引用对象与端口必须存在；非法连接不能提交 |
| IM-03 | 业务流程信息模型 | 流程定义包含节点、连线、条件、输入输出 Schema、字段映射、负责人、超时、重试、失败策略和版本；执行记录包含流程实例状态、节点尝试、实际输入输出引用及日志 | 发布前通过 DAG、字段映射和节点契约校验；每个流程实例及节点尝试可追溯定义版本、冻结输入和实际输出 |
| IM-04 | 标准规范与规则信息模型 | 标准与条款版本、效力、适用条件、参数映射、判据表达式、结论模板、严重级别及条文出处 | 每条执行结果锁定规则版本；规则缺项、单位冲突或测试失败时不得发布 |
| IM-05 | 计算任务与结果信息模型 | 模型、算法、适配器与环境版本、输入快照、工况、时间基准、状态、日志、错误、结果清单和质量标记 | 正式结果可复现并关联工程对象；终态不可改写；重试形成新尝试记录 |
| IM-06 | 成果报告信息模型 | 模板版本、模型/任务/运行尝试/校核/知识/审批引用、渲染器与字体包版本、文件清单、格式、哈希、签名、状态和保留策略 | 报告中的结构化数值可反查来源；发布文件不可覆盖；签署封套绑定正文哈希 |

## 6. 信息架构与核心流程

### 6.1 信息架构

- **管理端：** 登录、模型管理、算法管理、工作流管理、智能体管理、知识管理、水利组件、成果策略、系统管理。
- **用户端：** 登录、项目管理、拖拽工程构建、校核、AI 对话、模型运行、测试报告、评估报告、成果管理。

### 6.2 核心用户流程

1. **组件发布：** 领域专家定义端口和参数，绑定校核规则及求解器，在沙箱验证后审核发布。
2. **拖拽建模：** 工程师创建项目和模型，拖入组件并连接端口，配置参数和数据，实时校核后保存模型版本。
3. **方案计算：** 工程师基于已校核模型创建场景，绑定已发布算法，配置边界、工况和调度策略，执行联合仿真并对比结果。
4. **AI 文件生成：** 用户选择模型、运行成果和模板，输入自然语言要求，检索授权知识并生成带引用草案。
5. **人工复核：** 系统执行结构、规则与引用校验，工程师修改，校核人员复核，审批人员给出结论。
6. **成果交付：** 系统关联模型、运行、规则、知识及审批版本，批准后发布并归档交付包。

### 6.3 标准端到端流程

`创建项目 -> 选择模板 -> 拖拽拓扑 -> 配置参数 -> 编排算法 -> 基础校核 -> 规范校核 -> 创建场景 -> 联合仿真或调度 -> 结果评估 -> 生成文件草案 -> 人工复核 -> 审批发布 -> 成果归档`

### 7.4 拖拽式拓扑构建

画布同时表达水力对象、工艺对象、数据和控制信号。环路是否有效由组件规则和求解器能力判断，不得简单禁止所有环路。

| 编号 | 优先级 | 需求 | 验收要点 |
| --- | --- | --- | --- |
| TOP-01 | P0 | 组件库支持分类、搜索、收藏和拖入 | 拖入后生成全局唯一实例标识 |
| TOP-02 | P0 | 支持移动、缩放、框选、多选、复制、对齐、分组和撤销重做 | 建议保留不少于 50 步；重开后坐标、分组和视图稳定恢复 |
| TOP-03 | P0 | 通过类型化端口连接并显示方向 | 校验端口类型、介质、数据类型、方向和连接数；非法连接即时阻止并解释原因 |
| TOP-04 | P0 | 实时发现悬空端口、孤立节点、边界缺失和标识冲突 | 问题分错误、警告、提示；阻断错误未消除时不能运行或发布 |
| TOP-05 | P0 | 在属性面板编辑组件与连接参数 | 前后端使用同一 Schema；问题可从清单定位并高亮对象 |
| TOP-06 | P1 | 支持子模型折叠、小地图和大型拓扑导航 | 可按编码、类型、错误状态定位；折叠不改变模型语义 |
| TOP-07 | P2 | 支持 GIS 底图、坐标和里程桩号 | 坐标系与高程基准明确；底图不可用不影响拓扑编辑 |
| TOP-08 | P0 | 通过自然语言生成拓扑草案 | 只使用已发布组件；展示新增、修改、删除差异，确认后才写入草稿 |
| TOP-09 | P0 | 提供水利图元、端口吸附和结构树导航 | 连线后同步生成拓扑关系与结构树；画布、结构树、属性面板和问题清单选中状态双向联动 |

拓扑业务规则：

- 连接必须满足端口类型、方向、介质、量纲和数据类型兼容性。
- 双向流、回流工艺或环网组件必须由模板显式声明，求解器须支持其语义。
- 控制信号不能直接连接水力端口，必要时通过控制器或转换组件连接。
- 单连接端口达到最大连接数后禁止继续连接。
- 允许多个独立子系统，但每个可运行子系统必须具备完整边界条件。
- 删除组件前展示连接、工作流、运行和成果依赖；已被正式对象引用时只能停用或归档。

### 7.6 算法、工况与联合仿真

算法既可以是平台内已发布的公式、逻辑、PID 或调度组件，也可以通过适配器接入外部模型。MVP 重点支持算法资产治理、输入输出映射和一个专业求解器与算法或控制模型之间的基础联合仿真，不以通用代码开发环境为目标。

| 编号 | 优先级 | 需求 | 验收要点 |
| --- | --- | --- | --- |
| ALG-01 | P0 | 注册并版本化管理水文、水动力、控制和调度算法资产 | 记录算法类型、来源、输入输出 Schema、单位、依赖、运行环境、许可、负责人和版本；已发布版本不可原地修改 |
| ALG-02 | P0 | 通过组件或工作流编排算法调用关系 | 仅允许连接类型、方向、量纲和采样语义兼容的输入输出；工作流图禁止回边，算法图阻断求解器不支持的瞬时代数环，允许显式状态或延迟且求解器支持的反馈环 |
| ALG-03 | P0 | 将算法方案绑定到工程模型和方案场景 | 场景可覆盖边界、初值、计算时段、时间步长、事件和调度策略，但不修改基础模型或算法版本 |
| ALG-04 | P0 | 执行基础联合仿真和调度验证 | 支持至少一个专业求解器与算法或控制模型的时间同步、数据交换、事件传播、超时与失败处理；全部交换数据可追溯 |
| ALG-05 | P0 | 校验并冻结算法运行上下文 | 运行前校验输入完整性、单位、时间基准和版本兼容性；快照锁定算法包、依赖、配置、随机种子及环境哈希 |
| ALG-06 | P1 | 接入自定义算法包 | 在隔离环境执行安全扫描、签名、资源配额和接口契约测试；未通过沙箱验证不得发布 |
| ALG-07 | P1 | 支持多求解器联合仿真 | 明确主时钟、步长协商、数据交换点、收敛条件和失败传播策略；使用跨求解器黄金算例验证结果与复现性 |

模型适配器对外提供统一能力描述、输入校验、任务提交、状态查询、结果获取、取消和健康检查，屏蔽不同专业模型的协议及运行差异。

| 编号 | 优先级 | 需求 | 验收要点 |
| --- | --- | --- | --- |
| ADP-01 | P0 | 建立模型服务目录和能力清单 | 记录模型名称、版本、适用场景、输入输出 Schema、单位、调用模式、限制、许可和健康状态 |
| ADP-02 | P0 | 配置点位、字段、单位和数据结构映射 | 支持时间、数组、枚举、缺失值和质量标记转换；转换规则版本化且可用样例数据预览 |
| ADP-03 | P0 | 统一模型运行任务语义 | 所有运行先创建任务并返回任务 ID；适配器内部可同步调用短模型，平台对外仍以可查询任务记录为权威 |
| ADP-04 | P0 | 标准化模型结果并关联工程对象 | 结果清单包含 Schema、单位、质量标记、对象关联、文件地址与哈希、执行环境和适配器版本 |
| ADP-05 | P0 | 执行接口与数据质量检查 | 校验认证、时间戳、时间基准、单位、有效标记、字段完整性、超时和返回值；失败不得写入正式结果 |
| ADP-06 | P0 | 提供连接测试、模拟请求和契约测试工具 | 不依赖真实模型即可验证正常、缺字段、错单位、超时、取消、重试、重复提交及异常返回 |

### 7.8 工作流编排

MVP 采用有向无环图编排，支持人工任务、规则任务、仿真任务、AI 任务、审批网关和有界迭代复合节点。流程定义本身不得产生回边；迭代逻辑封装在节点内部，并必须配置最大次数、收敛条件和超时。任意循环、复杂补偿及跨组织联合审批不进入 MVP。

| 编号 | 优先级 | 需求 | 验收要点 |
| --- | --- | --- | --- |
| WF-01 | P0 | 图形化配置节点、连线、输入输出和负责人 | 发布前校验缺失输入、类型冲突、无出口节点和非法循环 |
| WF-02 | P0 | 支持串行 DAG、人工审批和条件网关 | 节点定义超时、重试、失败策略、权限和日志级别 |
| WF-03 | P0 | 工作流模板版本化 | 已发布模板不可原地修改；项目实例锁定模板版本 |
| WF-04 | P0 | 实例支持暂停、继续、取消和失败节点重试 | 重试不得重复产生已成功副作用；成功节点输出不可篡改 |
| WF-05 | P0 | 人工审批记录完整证据 | 记录审批人、意见、时间、结论和所审输入版本；退回后生成新版本 |
| WF-06 | P1 | 支持并行、定时、事件触发和通知 | 触发去重；汇聚规则明确；通知失败不改变业务状态 |
| WF-07 | P0 | 支持节点间字段级数据映射 | 校验字段类型、单位、必填项、默认值和转换表达式；发布前展示完整映射，运行记录保存实际映射版本 |
| WF-08 | P0 | 支持项目流程自定义、保存和复用 | 项目流程以草稿创建，经校验后在项目内发布；升级形成新版本；组织级模板必须由工作流管理员审核 |
| WF-09 | P0 | 支持有界迭代复合节点 | 节点声明初始输入、迭代输出、最大次数、收敛判据、超时和失败策略，并在收敛、达到上限或超时时确定性退出 |

节点类型至少包括数据导入与预处理、模型完整性校核、规范校核、模型编译、仿真运行、控制与调度、AI 草案、报告生成、人工复核、审批、条件判断、通知及外部 API。

### 7.9 知识库与知识治理

标准入库链路：`上传 -> 安全扫描 -> 解析或 OCR -> 结构恢复 -> 切片 -> 元数据补录 -> 质量检查 -> 建索引 -> 人工审核 -> 发布`。

只有已发布且在有效期内的知识默认进入生产检索。

MVP 默认面向可直接提取文本的电子文档，具体支持格式为 TBD。KB-02 与 KB-03 的 P0 范围是保留原生电子表格和公式的已有结构并避免无语义切断，不包含扫描件、跨页复杂表格或公式识别；后者与 OCR 按 P1 规划。若立项确认扫描件为一期刚需，应同步调整 KB-07 优先级、解析器选型和验收样本。

| 编号 | 优先级 | 需求 | 验收要点 |
| --- | --- | --- | --- |
| KB-01 | P0 | 批量上传、断点续传和重复检测 | 按文件哈希识别重复；失败重试不生成重复记录 |
| KB-02 | P0 | 解析正文、标题、页码、列表、表格、图片说明和附件关系 | 任一切片可回溯至原文件、页码、章节和表格位置 |
| KB-03 | P0 | 按标题层级、条款和语义切片 | 强制条文、公式、单位和表格不得无语义截断；保留父子及相邻关系 |
| KB-04 | P0 | 管理业务、权限、版本、效力和技术元数据 | 缺少必填元数据不得发布；水利词表由领域专家治理 |
| KB-05 | P0 | 建立向量、关键词和元数据索引 | 索引任务可观察、可重建；记录解析器和嵌入模型版本 |
| KB-06 | P0 | 支持审核、发布、撤回、废止和版本替代 | 新版本不覆盖旧版本；历史任务保留知识快照标识，访问快照正文时仍执行当前权限和强制下架策略 |
| KB-07 | P1 | 支持扫描件 OCR 与低置信度复核 | 低置信度页面进入人工队列，不直接进入生产索引 |
| KB-08 | P1 | 规则冲突、失效和更新提醒 | 冲突不自动裁决；展示效力、适用条件和来源 |

知识元数据至少包括：

- 唯一标识：文档 ID、版本 ID、切片 ID、内容哈希。
- 业务范围：租户、组织、项目、流域、区域、专业、水利对象类型。
- 文件属性：标题、文号、文档类型、发布单位、语言、原文件地址。
- 版本效力：版本号、发布日期、生效日、失效日、现行或废止、替代关系。
- 知识属性：章节、条款、关键词、规则类型、适用阶段、组件类型。
- 权限属性：密级、可见组织、可见项目、可见角色、知识负责人。
- 技术追踪：页码、版面位置、解析器、OCR 置信度、嵌入模型、索引时间。
- 治理信息：创建、审核、发布人员及意见、时间和废止原因。

### 7.10 标准规范与可执行规则

标准规范库保存原始文档与条款，规则库保存经领域专家审核、可由确定性规则引擎执行的结构化规则。AI 可以辅助拆解候选规则，但不得绕过审核直接发布或执行。

| 编号 | 优先级 | 需求 | 验收要点 |
| --- | --- | --- | --- |
| RUL-01 | P0 | 建立标准规范台账 | 管理标准名称、编号、版本、发布与实施日期、适用对象、适用工艺、来源文件、有效状态和替代关系 |
| RUL-02 | P0 | 按五要素结构化校核规则 | 每条规则必须包含适用范围、参数映射、判据表达式、结论模板和条文出处；缺少任一要素不得发布 |
| RUL-03 | P0 | 支持常用确定性判据 | 支持数值比较、区间判断、公式计算、查表插值和多条件组合；明确单位、精度、边界包含关系和空值策略 |
| RUL-04 | P0 | 按案例、对象、工况和效力自动匹配规则 | 匹配结果展示命中原因、适用条件和版本；冲突规则不自动裁决，交由授权人员处理 |
| RUL-05 | P0 | 结构化保存规则执行结果 | 记录对象、属性路径、指标、实际值、规范值、规则与条款版本、结论、问题说明、执行时间和输入快照 |
| RUL-06 | P0 | 发布前验证规则并支持即时复核 | 每种表达形式覆盖正常值、边界值、异常值、缺失参数和单位冲突样例；参数修正后可重新执行并保留前后结果 |

### 7.11 检索增强生成

检索链路为：意图识别、服务端权限过滤、查询改写与水利同义词扩展、向量和关键词混合检索、元数据过滤、基础重排序、规则时效检查、上下文组装、生成及引用校验。

| 编号 | 优先级 | 需求 | 验收要点 |
| --- | --- | --- | --- |
| RAG-01 | P0 | 在服务端完成权限预过滤和混合检索 | 关键词、向量和元数据检索只处理当前用户有权访问的内容；不得先召回越权内容再在界面隐藏 |
| RAG-02 | P0 | 按项目、专业、对象、地域、版本和效力过滤并执行基础重排序 | 默认优先现行有效且适用范围匹配的知识；过滤与排序参数写入生成记录 |
| RAG-03 | P0 | 冻结每次生成使用的知识快照 | 保存文档版本、切片、检索分数和排序结果；快照冻结内容版本但不冻结访问授权 |
| RAG-04 | P0 | 对生成结论执行引用完整性和一致性校验 | 关键结论缺少可定位引用、引用失效或证据不支持结论时，不得标记为已验证或进入发布 |

- 默认优先现行有效、地域匹配、项目匹配和模型类型匹配的知识。
- 同一问题存在冲突规则时，展示冲突、效力和适用条件，由授权人员处理。
- 每次生成固定知识快照，保存文档版本、切片、检索分数和重排结果。
- 每个关键结论必须展示文件标题、文号、版本、页码或条款、原文片段、效力状态和跳转入口。
- 引用缺失、定位失败或与结论不一致时，对应内容不能标记为已验证，也不能进入正式发布状态。

AI 必须遵循以下门禁：

1. 输出默认状态为“草案”。
2. 关键结论必须有可定位、有效且授权可见的引用。

5. 草案必须经过具备权限的人员复核与审批，才能形成正式成果。
6. AI 不能发布成果、签署校核结论或向生产控制系统下发指令。

## 8. 核心状态模型与业务规则

### 8.1 状态模型

| 对象 | 状态及主要流转 |
| --- | --- |
| 项目 | 可编辑 -> 已归档；归档后只读，恢复编辑须具备项目管理权限并记录审计 |
| 组件模板 | 草稿 -> 测试中 -> 待审核 -> 已发布 -> 已停用；审核退回后回到草稿 |
| 工程模型 | 草稿 -> 待校核 -> 校核退回或校核通过 -> 已发布 -> 已归档 |
| 算法模型 | 草稿 -> 沙箱测试 -> 待审核 -> 已发布 -> 已停用；修改已发布算法必须生成新版本 |
| 校核问题 | 待处理 -> 已确认 -> 已修复或已豁免 -> 已复核；驳回后回到待处理 |
| 计算任务与运行尝试 | 任务为排队、运行中、成功、失败、已取消或超时；首次执行与每次重试均创建独立运行尝试，任务终态和历史尝试不可改写 |
| 工作流模板 | 草稿 -> 待审核 -> 已发布 -> 已停用 |
| 工作流实例 | 待启动 -> 运行中 -> 已暂停、已完成、已失败或已取消 |
| 知识文档 | 已上传 -> 解析中 -> 待复核 -> 待审核 -> 已发布 -> 已撤回或已废止 |
| AI 产物 | 生成中 -> 草案 -> 差异确认 -> 确定性校验 -> 待复核 -> 退回或已通过；通过后仍需进入成果审批 |
| 成果 | 草稿 -> 待审核 -> 退回或已批准 -> 已发布 -> 已归档 |

### 8.2 数据与版本规则

- 所有项目、组件、模型、算法、场景、规则、知识、工作流、运行和成果使用全局唯一标识。
- 已发布对象不可原地修改；变更形成新版本，旧版本可查询和追溯。
- 文件、结构化模型、规则包和成果包保存内容哈希。
- 正式运行快照记录模型、算法、场景、组件、数据、规则、知识、提示模板、求解器和环境版本。
- 参数记录值、单位、来源、修改人、修改时间和前后差异。
- 被引用或已发布对象只能停用或归档；仅未被引用的草稿可物理删除。
- 工作流开始时冻结输入；修改输入必须取消当前实例并重新发起。
- 成果必须可反向追溯至工作流实例、计算任务、成功运行尝试及全部输入版本。
- 知识快照冻结内容与版本，不冻结访问授权；查看历史正文时重新执行当前 ACL，涉密升级、版权撤回或安全隔离可强制阻断正文，仅保留审计元数据。
- 登录、查看、下载、生成、修改、审批、发布、废止和权限变更均形成审计事件。

### 8.3 校核与例外规则

- 阻断错误未消除时，模型不得运行、送审或发布。
- 规则结果包括通过、不通过、警告、无法校核和不适用。
- 豁免必须填写原因、依据、处理人、审批人和有效范围，不能删除原问题。
- 规则版本升级不追溯改变历史结论；重新校核产生新记录。
- 相同快照在同一求解器版本和容差设置下应得到一致结果。

## 9. AI 质量、评测与异常处理

### 9.1 AI 上线门槛

| 维度 | 指标 | 建议门槛 | 验证方法 |
| --- | --- | --- | --- |
| 解析 | 受支持文档解析成功率 | 不少于 98% | 按格式和扫描质量分层统计 |
| 原文定位 | 切片到页码、章节或表格定位完整率 | 100% | 随机抽检与自动链接校验 |
| 检索 | Recall@10 与 nDCG@10 | 不少于 90% 与 0.80 | 不少于 200 个领域问答 |
| 引用 | 引用存在率与结论一致率 | 100% 与不少于 98% | 专家双人评分，争议仲裁 |
| 忠实度 | 关键结论有证据且不歪曲原文 | 不少于 95% | 覆盖过期、冲突和不适用规则 |
| 结构化设计 | Schema 合法率和提交前强校验 | 100% | 不少于 50 个设计任务 |
| 校核报告 | 报告与规则及仿真结果一致率 | 不少于 98% | 不少于 50 个校核任务 |
| 权限安全 | 跨组织、跨项目或越密级泄漏 | 零容忍 | 越权与提示注入专项测试 |
| 人工效果 | 首次通过或仅轻微修改比例 | 不少于 70% | 按专业与任务难度分层 |
| 性能 | 检索与完整设计草案 P95 | 2 秒内与 60 秒内 | 不含外部仿真时长 |

上线阻断项：引用伪造、严重规则漏检超标、跨项目或越密级泄漏、未经确认写入正式模型、绕过确定性校验，以及提示注入导致模型服从文档指令、隐藏或伪造引用、泄漏上下文或越权调用任何工具。上述提示注入攻击成功率和敏感上下文泄漏率均须为 0。

### 9.2 降级与异常处理

| 场景 | 系统行为 |
| --- | --- |
| 向量服务不可用 | 降级为关键词和元数据检索，并明确提示语义检索不可用 |
| 大模型超时或不可用 | 保留会话和任务上下文，允许重试，并提供模板化人工流程 |
| 解析置信度过低 | 文档进入待复核，不写入生产索引 |
| 证据不足 | 追问或标记证据不足，不输出确定性结论 |
| 规则冲突 | 展示条款、效力和适用条件，交由授权人员处理 |
| 引用定位失败 | 对应结论不得进入已验证或发布状态 |
| 模型校验失败 | 保留草案并展示错误，不允许提交正式模型 |
| 达到配额 | 停止新增生成，保留已完成结果并通知用户和管理员 |

## 10. 技术规格

### 10.1 逻辑架构

平台采用分层、模块化、服务化架构，以水利业务对象模型为数据基础，以可视化工作流为业务组织方式，以标准规范和专业机理模型为专业能力，以自动校核与成果生成为业务闭环。

| 层级 | 组成 | 核心职责 |
| --- | --- | --- |
| 前端应用层 | 管理端、用户端、拓扑画布、工作流设计器、流程监控、校核、报告和 AI 对话 | 对象建模、参数配置、流程编排、任务操作、结果展示和人工审核 |
| 业务服务层 | 项目、对象、组件、模型、场景、知识、工作流、校核、成果和系统管理服务 | 领域规则、状态机、版本、权限、审批和业务事务 |
| 模型与规则服务层 | 模型目录、适配器、任务调度、联合仿真、规则引擎、结果标准化、AI 编排与护栏 | 专业模型调用、确定性校核、AI 工具调用和计算资源隔离 |
| 数据存储层 | 关系数据库、对象存储、时序存储、全文与向量索引、缓存 | 权威元数据、文件、监测与结果时序、检索派生数据和临时状态 |
| 集成接口层 | API 网关、十项标准接口、数据库/文件/API 适配器、事件和状态推送 | 认证、授权、限流、幂等、协议转换、字段映射和外部协同 |
| 基础支撑层 | 身份、密钥、配置、消息与任务队列、日志、指标、链路、告警、备份恢复和部署平台 | 安全、可观测、弹性、容灾和运维治理 |

架构依赖规则：前端不得直连数据存储；外部系统不得绕过集成接口层调用内部存储；AI、工作流、规则和模型适配器必须通过业务服务执行权限、版本及状态校验；索引和缓存不得保存唯一业务事实。

### 10.2 候选技术栈

以下均为候选方案而非冻结选型。架构评审须结合私有化能力、许可证、团队技能、黄金算例性能、故障恢复和总体成本完成 POC，并在 D-10 决策后形成架构基线。

| 领域 | 候选方案 | 选型约束 |
| --- | --- | --- |
| Web 前端 | Vue 3、TypeScript、ECharts；拓扑/流程组件 TBD | 支持大型画布、可访问性、浏览器兼容和离线部署 |
| 核心后端 | Spring Boot 或 FastAPI；也可按清晰服务边界组合 | 禁止同一领域逻辑在两套框架重复实现；统一身份、错误码和追踪 |
| 工作流 | Flowable、Camunda、Temporal 或自研受限 DAG 引擎 | 通过人工任务、版本迁移、有界迭代、私有部署和故障恢复 POC |
| 事务与缓存 | PostgreSQL、Redis | Redis 仅用于缓存、锁和临时状态，不保存唯一业务事实 |
| 文件与时序 | 文件服务器或 S3 兼容对象存储；时序数据库 TBD | 文件具备版本、哈希和权限；时序选型按规模与查询模式决定 |
| 检索与向量 | OpenSearch/Elasticsearch；pgvector 或独立向量库 | 权限预过滤、可重建、中文水利检索质量和运维复杂度 |
| 消息与任务 | RabbitMQ、Kafka 或工作流引擎内置机制 | 支持幂等、重试、死信、优先级和资源隔离 |
| 部署与可观测 | Docker；Kubernetes、OpenTelemetry、指标与日志后端 TBD | 满足内网部署、密钥治理、备份恢复和冻结后的 SLO |

### 10.3 关键数据流

1. **组件发布流：** 管理端提交定义，服务端校验 Schema、端口、规则和适配器，沙箱测试后发布不可变版本。
2. **模型设计流：** 用户在画布编辑草稿，服务端增量校验并保存；送审时冻结模型和依赖快照。
3. **知识入库流：** 文件经安全扫描和解析，生成结构化内容及切片，经审核后写入全文与向量索引。
4. **AI 生成流：** 服务端先鉴权和检索，再调用目录、规则与校验服务，生成差异草案供人工确认。
5. **模型运行流：** 工作流冻结输入，计算服务调度求解器，结果和日志写入成果服务并触发审批。
6. **成果发布流：** 成果服务校验来源链、审批和文件哈希，发布不可变版本并按策略归档。

### 10.4 数据存储与一致性

| 数据类别 | 权威存储 | 关键约束 |
| --- | --- | --- |
| 项目、对象、拓扑、流程、规则、任务、权限和成果元数据 | 关系数据库 | 使用事务、外键或等效引用校验；发布对象不可变；所有正式记录带版本和内容哈希 |
| 模型输入输出、算法包、图片、附件和报告 | 对象存储或受控文件服务器 | 数据库保存文件 ID、版本、URI、哈希、大小、权限和关联对象；禁止只保存裸路径 |
| 监测数据和高频模型结果 | 关系库或时序数据库 | 按项目、对象、测点、时间和任务建立索引；统一时区、采样语义和质量标记 |
| 标准全文、文档切片与向量 | 全文及向量索引 | 由权威文档和元数据重建；索引异步时暴露状态，不得绕过当前权限 |
| 会话、缓存、分布式锁和临时任务状态 | Redis 或等效缓存 | 设置过期与容量策略；丢失后可由权威状态恢复 |

跨存储写入采用事务 Outbox/Inbox、幂等消费者或等效机制。外部数据库适配器默认只读；确需写入的数据先进入交换暂存区，经 Schema、权限、版本、单位和幂等校验后由业务服务提交，禁止直接写核心表。

### 10.5 五类集成角色与责任边界

附件中的五类“外部系统”在产品契约层定义为五类逻辑集成角色。十项接口及其模拟服务均为 P0；角色可由平台内置模块、真实外部系统或混合部署实现，只有 D-13 选择外部或混合实现的角色才要求真实外部联调。

| 外部系统 | 对接能力 | MBD 权威职责 | 外部系统边界 |
| --- | --- | --- | --- |
| 智能体平台 | 查询获授权对象、规则、流程、模型状态和成果；创建草案或启动已发布流程 | 权限、上下文、草案状态、工具白名单、人工审核和审计 | 不得直接发布模型、规则、校核结论或成果；代理调用保留用户与服务双重身份 |
| 数据库或数据平台 | 提供对象、历史时序、标准规则和任务交换数据 | 统一对象编码、Schema、版本、单位、时间基准和导入审核 | 默认只读或暂存区交换，不得直接修改 MBD 核心表 |
| 专业模型服务 | 提供混凝沉淀、生化反应、渠道水力、控制或调度计算 | 输入快照、任务编排、权限、状态、结果标准化和结果副本 | 负责计算实现及模型内部正确性，必须公开版本化输入输出契约 |
| 报告服务（内置或外部） | 渲染模板、转换 DOCX/PDF、回传生成状态与文件 | 成果元数据、来源链、审批、归档和权威文件哈希 | 不修改冻结数据和审批状态，输出必须回存 MBD 并校验哈希 |
| 开放平台 | 应用与服务注册、凭据、配额、接口文档、样例和沙箱入口 | 业务数据和权限策略 | 不拥有业务数据，不得将示例凭据用于生产 |

智能体和报告能力无论采用平台内置、外接或混合模式，均遵守同一业务接口、权限、版本和契约测试；最终物理部署及真实外部联调范围由 D-13 冻结。

### 10.6 十项标准化业务接口

| --- | --- | --- | --- | --- |
| INT-01 | 对象模型查询 | 项目、工程或对象标识，目标版本 | 对象属性、端口、测点和拓扑；同步 | 支持版本和权限过滤，返回 Schema 版本及单位 |

| INT-04 | 业务流程启动 | 已发布流程版本、项目、业务参数和输入快照 | 流程实例 ID 与启动状态；异步 | 返回任务标识，重复幂等键只创建一个实例 |
| INT-05 | 标准规范与规则查询 | 工艺、对象、场景、地域、标准编号、效力与版本 | 适用条款、规则和来源；同步 | 当前权限和效力过滤在服务端执行，冲突规则同时返回 |
| INT-06 | 模型服务目录查询 | 场景、模型类型、状态和版本条件 | 名称、版本、适用场景、输入输出 Schema、单位和调用要求；同步 | 仅返回已发布且有权使用的模型能力 |

| INT-09 | 校核结果交换 | 对象、规则版本、实际值、规范值、结论、依据和输入快照 | 接收状态与结果版本；同步或批量异步 | 结果追加写入，不覆盖历史；批量导入逐条返回错误 |
| INT-10 | 成果报告交换 | 报告或模板版本、关联任务、格式、文件清单和哈希 | 交换任务 ID、最终文件、状态与哈希；异步 | 最终文件回存 MBD，校验来源链、权限、格式和内容哈希 |

### 10.7 接口公共契约

- 支持数据库接口、文件接口和 API 三类接入方式；正式业务提交必须通过业务 API，数据库或文件导入只允许写入交换暂存区，经校验后由业务服务提交；文件交换采用版本化 JSON 或文件清单。
- API 使用 HTTPS、UTF-8 JSON 和版本化路径；WebSocket 或事件仅用于状态推送，不作为权威写入通道。
- 请求携带服务身份、用户委托身份、租户、项目、追踪上下文和幂等键；租户身份由服务端可信上下文推导。
- 时间采用 RFC 3339，单位使用受控字典；大文件通过受控上传或预签名地址交换，普通 JSON 仅传文件清单与哈希。
- 每项接口独立交付接口标识、地址、输入输出字段、单位、认证、权限矩阵、稳定错误码、版本策略、SLO、OpenAPI/JSON Schema、调用示例和模拟服务。
- 十项接口分别执行提供方与消费方契约测试，覆盖正常、缺字段、错单位、未授权、重复提交、超时、取消、回调重放和版本不兼容。
- 破坏性变更必须升级接口版本并提供迁移期；同一幂等键的并发请求只能产生一次业务副作用。

## 11. 安全、隐私与审计

| 控制域 | 要求 |
| --- | --- |
| 身份与授权 | 采用 RBAC 与 ABAC 组合；角色控制动作，组织、项目、密级和状态控制数据范围 |
| 最小权限 | 默认拒绝；页面与 API 同源鉴权；高风险操作二次确认；支持职责分离 |
| 数据隔离 | 关系库、对象存储、全文索引、向量检索和 AI 上下文执行同一权限过滤 |
| 加密与密钥 | 传输和存储加密；密钥进入专用管理系统，不写入代码、日志或提示词 |
| 模型数据政策 | 默认禁止模型供应商使用业务数据训练；外部调用受密级和数据出境策略约束 |
| 文件安全 | 恶意文件扫描、格式伪装检测、压缩炸弹限制、宏和脚本隔离；解析过程沙箱化 |
| 提示注入 | 文档作为不可信证据隔离；工具白名单；高风险调用需要确定性授权和参数校验 |
| 审计与留存 | 关键操作日志不可篡改；提示词、原文和个人信息按最小必要原则保存 |
| 合规 | 等保等级、数据分级、日志留存、涉密边界、电子签章和归档要求均为 TBD |

审计事件至少记录：操作者、组织、项目、会话、动作、对象及版本、前后值摘要、时间、来源地址、结果、失败原因和追踪 ID。

日志按操作、接口调用、模型运行、工作流、异常和安全审计六类管理，覆盖登录、参数修改、模型及规则版本、流程节点、第三方调用、审批和报告导出。六类日志使用统一事件 ID、追踪 ID 和任务 ID 关联；不得记录密码、令牌、密钥或未经脱敏的敏感正文。

| 备份对象 | 策略 | 恢复校验 |
| --- | --- | --- |
| 关系数据库与审计记录 | 定期全量备份和增量/日志备份，加密并跨故障域保存 | 恢复项目、权限、版本和状态机后满足核心元数据 RPO/RTO |

## 13. 交互与错误处理原则

- 始终显示当前项目、模型版本、方案场景和编辑状态，跨模块跳转不丢失上下文。
- 错误在产生位置即时提示，并说明原因、影响和修复路径。
- 错误、警告和提示使用文字与图标共同区分，颜色不得作为唯一状态表达。
- 删除、覆盖、发布、回滚和取消运行等高风险动作展示影响范围，并提供二次确认或恢复机制。
- 解析、索引、仿真和报告生成异步执行，显示排队、进度、取消和失败重试。
- 画布支持键盘操作、缩放、对象搜索和问题定位。

### 14.2 端到端验收场景

1. **污水处理闭环：** 建立 AAO 生物池复合对象（含厌氧、缺氧、好氧单元）、二沉池、回流、曝气、加药和监测对象，构建水、气、药及两类回流网络，完成多工况计算、校核、六类报告中适用报告、审批和归档。
2. **明渠输水闭环：** 建立渠道、倒虹吸、闸、分水口、泵站、量水设施和测点，完成多级渠系建模、参数与边界配置、水力计算、校核、报告、审批和归档。
3. **规则闭环：** 五种判据分别执行正常、边界、异常、缺失和单位冲突样例；修改参数后即时复核，历史结论仍绑定原规则版本。
4. **界面联动：** 从问题定位画布对象与字段，从曲线或表格定位对象和工况，从对象打开适用规则、运行记录和报告来源。
5. **报告闭环：** 六类报告由冻结快照确定性生成适用的 DOCX/PDF；审批后签署封套绑定正文哈希，归档包可反向追踪全部来源。
6. **十项接口闭环：** 在模拟环境逐项完成正常、缺字段、错单位、未授权、重复提交、超时和版本不兼容测试，再串联对象、流程、模型、校核与报告交换。
7. **算法联合仿真：** 将已发布控制或调度算法绑定工程模型，在指定工况下完成时间同步、数据交换、运行复现和异常处理验证。
8. **有界迭代：** 迭代节点分别因收敛、达到最大次数和超时退出；流程图不存在回边，历史迭代输入输出完整可查。
9. **可运行性与等级：** 使用经领域专家确认的正反黄金算例，验证指定工况下的可运行性、等级结论、成立条件、无法判级状态和证据链。
10. **组件、算法和规则升级：** 发布新版本后历史模型及结果保持可追溯，新项目可选新版本，升级影响可预览并回归黄金算例。
11. **知识与 AI：** 新规范替代旧版后，新任务默认使用现行知识；AI 模型或文件草案展示引用、假设和差异，未确认不写入，未审批不发布。
12. **权限隔离：** 未授权用户无法通过页面、搜索、文件、直接链接、数据库适配器、API、WebSocket 或 AI 获取其他项目数据。
13. **恢复审计：** 在隔离环境恢复模型、配置、运行、报告、审批和权限，核对哈希及引用，并通过追踪 ID 还原完整操作链。

### 14.3 发布门禁

- P0 需求验收通过率 100%，严重缺陷清零。
- 六类信息模型、两类业务案例、六类报告和十项接口的必测项全部通过。
- 黄金算例、权限隔离、引用真实性、状态机、版本链和恢复一致性测试全部通过。
- AI 达到引用、忠实度、结构合法率及安全门槛。
- 运维、备份恢复、应急停用和审计导出手册齐备。
- 领域、产品、安全、技术和试点用户共同签署上线意见。

## 18. 发布与运营机制

- 采用内部验证、受控试点、扩大试点和正式上线四个阶段，每阶段使用同一套黄金算例和安全回归集。
- 灰度期间保留人工流程作为回退；知识、AI 或求解器异常不影响用户查看既有模型与成果。
- 每周审查缺陷、校验失败、AI 采纳、引用问题和队列资源；每月审查成功指标与模型成本。
- 组件、规则、解析器、提示模板、嵌入模型和大模型升级均须版本化评测，禁止直接替换生产版本。
- 发现严重错误设计、越权泄漏或不可复现成果时，立即停用相关 AI 或适配器能力并保留审计证据。

## 附录 A：术语表

| 术语 | 定义 |
| --- | --- |
| MBD | Model-Based Design，基于模型的设计，以可计算、可验证模型驱动设计、仿真、校核和交付 |
| 组件模板 | 定义水利对象端口、参数、规则、样式和模型适配器的可复用标准资产 |
| 组件实例 | 组件模板在某个工程模型中的具体引用和配置 |
| 工程模型 | 由组件实例、连接、全局参数和子模型构成的水利系统表达 |
| 方案场景 | 在同一工程模型上定义的一组边界、初始条件、工况和调度策略 |
| 算法模型 | 具有版本化输入输出契约、单位、依赖和运行环境的水文、水动力、控制或调度算法资产 |
| 工作流实例 | 一次已发布流程定义的执行，是节点状态、输入输出和所创建计算任务的编排上下文 |
| 计算任务 | 针对一个冻结输入快照发起的一次模型或求解器计算请求，可包含一个或多个运行尝试 |
| 运行尝试 | 计算任务首次执行或重试形成的不可变执行记录，具有独立尝试标识、状态、日志和环境版本 |
| 六类信息模型 | 工程对象、拓扑关系、业务流程、标准规范与规则、计算任务与结果、成果报告六类跨模块数据契约 |
| 模型适配器 | 将专业模型能力、输入输出、任务状态和结果转换为平台标准契约的隔离模块 |
| 有界迭代节点 | 封装循环计算的复合工作流节点，必须通过收敛、最大次数或超时确定性退出，不在流程图形成回边 |
| 接口契约 | 接口的版本、身份、字段、单位、Schema、错误码、幂等、SLO、示例和兼容策略集合 |
| 运行快照 | 一次运行开始时冻结的模型、算法、数据、规则、知识、求解器和环境版本集合 |
| 规则集 | 按版本发布的确定性校核规则及其适用范围和来源 |
| 知识快照 | 某次 AI 生成固定使用的文档版本与切片集合 |
| RAG | Retrieval-Augmented Generation，先检索授权知识，再基于证据生成回答或草案 |
| Schema | 用于约束组件参数、拓扑或 AI 结构化输出的数据结构定义 |
| 黄金算例 | 由领域专家确认输入、预期结果和容差的参考模型，用于求解器与规则回归 |
| 内容哈希 | 对文件或结构化内容计算的摘要，用于识别版本和校验完整性 |
| P0、P1、P2 | 分别表示 MVP 必需、首期增强和中长期扩展 |
